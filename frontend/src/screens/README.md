# screens

화면 단위 React 컴포넌트. 라우팅, 레이아웃, 카드/리스트, 설정 UI 등 화면을 그리는
역할만 담당하며, 오디오/BLE 실시간 처리 로직은 core/audio, core/ble 모듈에 위임한다.

- Home — 시작 화면
- MusicSelect — 데모 음원 선택 화면
- Mixing — 믹싱 메인 화면 (비주얼라이저 포함)
- ModuleSettings — 물리 모듈 연결/설정 화면

Home(`/`)과 MusicSelect(`/music-select`)는 Figma 기반으로 구현되어 있습니다.
MusicSelect의 두 + 링크는 `/music-search?deck=left` 또는 `deck=right`로 이동합니다.
MusicSearch는 Figma 참조 앨범 목록과 이름 검색을 제공하며, 상세 화면과 실제 음원은 아직 연결되지 않았습니다.
Setting 화면은 기기 연결과 음원 설정을 제공합니다.

음악 미리듣기: 검색 카드 선택 시 하단 플레이어가 열립니다. 플레이어 +는 진입한 덱에 곡을 확정하며 URL의 left/right 값으로 선택을 보존합니다.
실제 음원은 아직 없습니다. src/screens/musicSelection.ts의 각 트랙 audioSrc에 실제 재생 URL을 설정하면 미리듣기 재생/일시정지/탐색이 연결됩니다. 현재는 음원 연결 대기를 표시합니다.
The Chase 외 항목은 앨범 참조 데이터를 사용하며 실제 트랙 목록과 길이는 추가 제공이 필요합니다. 파형은 Figma 참조 이미지이고 실제 오디오 분석 파형은 아닙니다.

Mixing(`/mixing?left=...&right=...`)은 한 곡 이상 선택하면 진입합니다.

## 실제 기기 입력 (2026-09-13)

홈의 Setting(`/settings`)에서 조그휠 BLE(BLEMIDI_1), 조그휠 USB(9600bps), 노브 BLE(BLEMIDI_2)를 연결합니다. 연결 상태와 유효 입력 수신 여부를 별도로 표시합니다. 노브는 기존 펌웨어의 K + Treble/Bass/Volume(각 0~100) 패킷을 사용하며, 세 값을 각각 위/중간/아래 도트에 반영합니다. 서로 다른 BLE 장치 3대가 아닌 한 모듈의 세 채널입니다. 실제 펌웨어 패킷이 다르면 파서 확인이 필요합니다.

- 조그휠: 터치 중 스크래치 샘플로 120ms 크로스페이드, 해제하면 멈춘 기본/베이스 위치에서 재개. 샘플 미등록이면 기존 곡을 유지합니다. 회전 각도는 센서 값이 아닌 장식 모션이며, 명세에 따라 터치는 오디오 전환에 사용합니다.
- 노브: Treble은 고역 필터, Bass는 별도 베이스 음원 볼륨, Volume은 전체 출력 볼륨. 세 도트 영역을 가로로 조작하거나 키보드 방향키로 테스트할 수도 있습니다.
- 슬라이더: 하드웨어 연결 없이 가운데 패널을 세로로 조작합니다. 기존 범위 0.9~1.1배(중앙 1배)를 사용합니다. 명세의 상세 항목에 따라 음량 대신 재생 속도로 해석했습니다.
- 음원: 기본 음원, 동일 시작점/길이의 베이스 보조 음원, 스크래치 샘플을 로컬 파일로 등록합니다. 등록 파일은 서버로 업로드하지 않으며 같은 탭의 화면 이동 시 유지됩니다. 새로고침하면 기본 설정으로 돌아갑니다. 제공된 `/audio/videoplayback.mp3`가 기본 음원이며, Setting에서 선택한 기본 음원이 믹싱에 적용됩니다. 음원이 없을 때 테스트 톤을 자동 재생하지 않습니다.
- 재생/일시정지/탐색/속도 변경 시 기본 음원과 베이스 보조 음원은 같은 AudioContext 시계와 위치를 사용합니다.
- 기존 `/test` 연결 진단 도구는 유지됩니다. 실제 BLE/USB 수신 및 실제 출력 음질은 장치와 음원으로 검증해야 합니다.

검증: `npm run build`, `npm run lint`, `node --test tests/mixing-audio.test.mjs` (frontend 디렉터리, Node 24).
